# SFT Book and Companion Adventure Standard

Version: 0.1
Status: working standard
Established from Maria Smith's direction on 30 July 2026

## Purpose

Every educational book will have a companion digital text adventure. The book
is the primary learning work. The game creates a playful loop that encourages
the learner to return to the literature, look more carefully, read with an
adult where appropriate and then use what was read in an interactive setting.

The game must never become a substitute authority, a faster route around the
reasoning or a reward system that values play time above understanding.

## The reading-first loop

Each companion level follows this order:

1. **Story situation** - a character meets a concrete problem.
2. **Learner choice** - the player spots, sorts, predicts, explains or checks.
3. **Honest response** - the game explains what the choice shows without
   shaming a different answer.
4. **Book bridge** - the game names the exact book pages that contain the
   demonstration or reasoning.
5. **Reading code** - an optional code printed in the book unlocks a bonus
   character response, clue, collectible or story detail.
6. **Return and apply** - the player uses the distinction learned from reading
   in a new game situation.

No scientific conclusion may be available only as an unexplained game reward.
The book bridge remains visible even when the learner answers correctly.

## Experience-before-vocabulary rule

A child-facing learning word must not appear as unexplained shorthand. The
learner first sees, hears or performs the distinction; the word is then named
and defined in plain language at first use. A labelled reveal or visible word
helper repeats that meaning. For example, the learner sees that no object has
been shown to inspect before meeting the short phrase *no example given*.

If a word cannot be explained without importing an unlearned technical term,
the activity must stay with the concrete experience and postpone the term.
Adult-facing exact language remains available in the guide.

## Reading-code rules

- Codes are short, pronounceable and printed on reveal or summary pages.
- A code never gates the required explanation, next core lesson or accessible
  route.
- A code may unlock a bonus hint, cosmetic clue star, character conversation,
  replay variation or optional extension.
- Entering a wrong code gives a neutral prompt to check the named book page.
- Codes must not reward buying, sharing personal data, daily return streaks or
  excessive play.
- The answer to a scientific question is not itself treated as a secret cheat
  code.
- Every code is versioned with the book so a revised edition cannot silently
  change an earlier adventure.

## Scientific authority

The companion consumes the same book claim-and-receipt map. It may translate
an admitted claim into a bounded activity, but it cannot admit, extend or alter
scientific knowledge. External game conventions are interface references only.

Each scene must preserve status language:

- admitted knowledge remains admitted knowledge;
- prediction remains prediction;
- correspondence remains correspondence;
- application remains application; and
- unfinished science remains `OPEN`.

The game must not reward a conventionally familiar answer when the SFT route
does not lawfully derive it.

## Educational balance

The intended loop is more reading, then better play - not more play in place of
reading. A typical level should take less time to play than the corresponding
book section takes to read and discuss. Bonus rewards deepen the story but do
not turn reading into a chore imposed between long play sessions.

Feedback praises observable actions such as noticing, explaining, checking and
keeping a disagreement. It does not label a child clever, slow, gifted or bad.

## Accessibility and safeguarding

- All actions work by keyboard, touch and assistive technology.
- Text is scalable and can be read aloud by the device.
- Colour is never the sole status cue.
- Motion is optional and respects reduced-motion preferences.
- Early-years companions collect no name, age, email, location, voice, camera
  image or behavioural analytics.
- Device-local progress is optional, visible and resettable.
- There are no advertisements, purchases, public leaderboards, chat, social
  pressure, streak loss or infinite-reward loops.
- An adult page explains the activity, scientific boundary and data behavior.

## Standard package

Each companion contains:

- a versioned content manifest linked to the book version;
- the complete playable adventure;
- a book-page and reading-code map;
- accessible labels and non-pointer controls;
- an adult information panel;
- deterministic answer and feedback logic;
- automated interaction and content-boundary checks;
- a local data and reset statement;
- licence and source history; and
- release notes and checksums.

## Publication approval

A working companion may be committed to the repository with its matching book
review version. It does not enter `publications/education/`, receive production
hosting or become an approved final educational publication until Maria Smith
explicitly approves the exact version and separately authorises any remote
hosting action required by repository governance.
