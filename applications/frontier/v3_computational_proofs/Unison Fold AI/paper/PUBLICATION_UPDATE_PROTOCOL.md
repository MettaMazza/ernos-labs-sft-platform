# Unison Fold AI publication-update protocol

## Current identity

The first standalone open-access preliminary version is `0.1.0-rc1`, DOI
`10.5281/zenodo.21726397`. It freezes the evidence reported by the versioned
paper and its source/evidence identities; it does not freeze or interrupt the
concurrently running model build. Later complete results must use Zenodo's
new-version action on this record so the preliminary chronology is preserved.

## Trigger and authority

A successor is prepared only when Maria Smith requests a publication update.
Maria Smith remains the scientific author and sole publication authority.
Preparing, editing, rendering, Git-staging, committing, pushing, creating a
release, assigning a DOI and publishing are separate actions; authority for one
does not imply another.

## Successor method

For every requested update:

1. read the current repository evidence rather than carrying forward remembered
   status;
2. verify the protected engine and verification-authority seals without
   modifying either authority;
3. preserve the preceding paper and PDF unchanged as historical records;
4. assign a new version and date to the successor paper;
5. identify every newly available result, correction, adverse record,
   resolution and open gate from current receipts;
6. update formal, computational and empirical statements only where current
   evidence authorises the change;
7. retain rejected candidates and superseded limitations in the chronology;
8. update the conceptual paper, reproducibility record, guidance audit,
   metadata and licence record as required;
9. render a new PDF and complete text, metadata and page-image checks;
10. run the existing verification suite without changing its specification;
    and
11. present the successor to Maria before any commit or remote action.

## Result-amendment rule

Later training, independent verification, unseen conversation, comparator or
manual Discord results enter only a successor version. They never silently
rewrite `0.1.0-rc1`. A favourable result cannot erase an earlier rejection; an
adverse result cannot be softened into a pass; and completion of an engineering
gate cannot be represented as admission of a new SFT law.

## Publication boundary

Maria Smith authorised the version 0.1.0-rc1 GitHub `main` push and standalone
Zenodo publication on 31 July 2026. That instruction does not authorise a
future version, release, DOI operation, upload or public deployment; each
successor remote action requires a new explicit instruction.
